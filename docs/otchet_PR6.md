## 4. Доработка индивидуального проекта

### 4.1. Структура шаблонов

```
guide_service/
├── templates/                       шаблоны уровня проекта
│   ├── base.html
│   ├── not_found.html
│   └── includes/navigation.html
├── homepage/templates/homepage/     index.html, page_not_found.html
├── guides/templates/guides/         guide_list.html, guide_detail.html,
│                                    includes/guide_card.html
├── routes/templates/routes/         route_list.html, route_detail.html,
│                                    includes/route_card.html
├── excursions/templates/excursions/ excursion_list.html, excursion_detail.html,
│                                    includes/excursion_card.html
└── schedules/templates/schedules/   schedule_list.html, schedule_detail.html,
                                     includes/schedule_status.html
```

В `guideservice/settings.py` каталог уровня проекта добавлен в `TEMPLATES`
как `'DIRS': [BASE_DIR / "templates"]`, а `'APP_DIRS': True` оставляет поиск
шаблонов в каталогах приложений.

### 4.2. Базовый шаблон и наследование

`templates/base.html` содержит общий каркас: `<!DOCTYPE html>`, `<head>` с
Bootstrap 5.3 и собственным CSS, логотип, навигацию, `<main>`, подвал и
подключение JavaScript. В нём два переопределяемых блока — `{% block title %}`
(по умолчанию «Экскурсионное бюро») и `{% block content %}`. Все дочерние
страницы начинаются с `{% extends "base.html" %}` и задают свой заголовок и
содержимое, поэтому общая разметка не дублируется.

### 4.3. Включаемые шаблоны

`templates/includes/navigation.html` — меню разделов сайта, подключается в
`base.html` строкой `{% include "includes/navigation.html" %}`. Карточки
списков вынесены в `guides/includes/guide_card.html`,
`routes/includes/route_card.html` и `excursions/includes/excursion_card.html`,
статус занятия — в `schedules/includes/schedule_status.html` (используется и
в списке, и в карточке занятия). Общий шаблон `not_found.html` показывает
сообщение, подсказку и ссылку возврата к списку; его вызывают view-функции
при ненайденном id.

### 4.4. Контекст, циклы и условия

View-функции только готовят данные: в `guides/views.py` список гидов
попадает в контекст под ключом `guides`, в карточке рядом с `guide`
передаётся `schedules`, а в `schedules/views.py` — `schedules`. В шаблонах
списки выводятся циклами `{% for guide in guides %}` с веткой `{% empty %}`
(«Гидов пока нет»), а условия `{% if %}` показывают статус гида
(`guide.is_active`) и занятия (`schedule.status`: «запланирована»,
«проведена», «отменена»). Связанные объекты выводятся через атрибуты:
`{{ schedule.excursion.title }}`, `{{ schedule.guide.name }}`.

### 4.5. Именованные URL и пространства имён

В `urls.py` каждого приложения задан `app_name`: `homepage`, `guides`,
`routes`, `excursions`, `schedules`. В шаблонах используются имена
`homepage:index`, `guides:list`, `guides:detail`, `routes:list`,
`routes:detail`, `excursions:list`, `excursions:detail`, `schedules:list`,
`schedules:detail`. Ссылки строятся тегом `{% url %}`:
`{% url 'guides:detail' guide.id %}`, `{% url 'schedules:list' %}`; жёстких
адресов в шаблонах нет.

### 4.6. Фильтры

`{{ guides|length }}` выводит количество записей в списке;
`{{ guide.name|default:"Без имени" }}` и
`{{ route.description|default:"Описание не заполнено." }}` подставляют текст
при пустом значении; `{{ guide.languages|join:", " }}` склеивает языки через
запятую; `{{ schedule.revenue|floatformat:0 }}` и
`{{ route.duration_hours|floatformat:1 }}` округляют числа. Фильтры меняют
только вывод и не считают бизнес-показатели: стоимость и скидки остаются в
методах классов.

### 4.7. Статические файлы

Собственные файлы лежат в `homepage/static/homepage/`: `css/style.css`,
`js/main.js`, `img/logo.png`. В первой строке `base.html` стоит
`{% load static %}`; CSS подключается как
`{% static 'homepage/css/style.css' %}`, логотип —
`{% static 'homepage/img/logo.png' %}`, скрипт —
`{% static 'homepage/js/main.js' %}`. `main.js` подставляет текущий год в
подвал (`<span id="current-year">`), поэтому год не записан в HTML.
Bootstrap 5.3 остаётся подключённым по CDN, но собственные стили проекта
обязательны: логотип, рамки карточек, полоса у карточки гида, цвет
навигации.

### 4.8. Удаление функции page()

Функция `page()` из ПР5 удалена из `homepage/views.py`, вызовов
`HttpResponse(page(...))` в проекте не осталось. HTML больше не собирается
в Python: каждая view-функция возвращает
`render(request, "имя_шаблона.html", context)`.

## 5. Результат работы

В результате ПР6:

* веб-часть переведена на Django Template Language, HTML в `views.py`
  не осталось;
* создан базовый шаблон `base.html` и настроено наследование для всех
  страниц;
* повторяющиеся фрагменты вынесены в `include`: навигация, карточки гидов,
  маршрутов и экскурсий, статус занятия;
* данные передаются через контекст, в шаблонах используются циклы, условия
  и фильтры;
* все ссылки строятся по именованным маршрутам с пространствами имён;
* подключены собственные CSS, JavaScript и логотип;
* удалена функция `page()`, обновлён `README.md`.

## 8. Вывод

В ПР6 веб-часть проекта переведена на шаблоны Django: HTML отделён от
Python, общий каркас задаётся в `base.html`, повторяющиеся фрагменты
вынесены в `include`, ссылки строятся по именованным маршрутам с
пространствами имён, а CSS, JavaScript и логотип подключаются через
`static`. Фильтры не заменяют бизнес-логику: они только форматируют уже
подготовленное значение, а правила — скидки, проверку мест, занятость
гида — остаются в методах классов и во view, где их можно проверить
тестами.
