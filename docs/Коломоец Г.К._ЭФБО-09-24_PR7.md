## 4. Доработка индивидуального проекта

### 4.1. Структура базы данных

Данные проекта хранятся в файле `data/guideservice.sqlite`. Сущности
предметной области ПР3 соответствуют четырём таблицам.

| Таблица | Поля и типы | Ключи и связи |
| --- | --- | --- |
| `guides` | id INTEGER, name TEXT, specialization TEXT, languages TEXT, experience_years INTEGER, rating REAL, is_active INTEGER | id — первичный ключ |
| `routes` | id INTEGER, name TEXT, description TEXT, duration_hours REAL, distance_km REAL, difficulty TEXT, required_languages TEXT, is_active INTEGER | id — первичный ключ |
| `excursions` | id INTEGER, title TEXT, route_id INTEGER, kind TEXT, base_price REAL, max_participants INTEGER, min_age INTEGER, languages TEXT, is_active INTEGER | id — первичный ключ; route_id → routes.id |
| `schedules` | id INTEGER, excursion_id INTEGER, guide_id INTEGER, date TEXT, start_time TEXT, booked INTEGER, status TEXT, note TEXT | id — первичный ключ; excursion_id → excursions.id, guide_id → guides.id |

В `sql/schema.sql` таблицы создаются командой `CREATE TABLE IF NOT EXISTS`;
у обязательных полей заданы `NOT NULL` и при необходимости `DEFAULT`, у
первичных ключей — `INTEGER PRIMARY KEY`. Внешние ключи объявлены в самих
таблицах, а проверка связей включается командой `PRAGMA foreign_keys = ON` —
и в файле схемы, и в каждом подключении `get_connection()`. По внешним
ключам и дате созданы индексы `idx_excursions_route`,
`idx_schedules_excursion`, `idx_schedules_guide` и `idx_schedules_date`.
Списки языков хранятся одной строкой через запятую, чтобы по ним работал
`LIKE`; дата — строкой `YYYY-MM-DD`, логическое `is_active` — числом 0/1.

### 4.2. Перенос данных из JSON

Скрипт `db/import_json.py` читает JSON-файлы функциями ПР3
(`storage.load_all`), поэтому в базу попадают уже проверенные объекты
предметной области. Записи вставляются методом `executemany()` с
заполнителями `?`; языки склеиваются в строку, `is_active` приводится к
0/1. Перед импортом таблицы очищаются в порядке от зависимых к основным, а
порядок вставки — `guides` → `routes` → `excursions` → `schedules` — не
нарушает внешние ключи. Перенесено 6 гидов, 5 маршрутов, 5 экскурсий и
8 занятий.

### 4.3. Файлы и модули

`sql/schema.sql` — команды создания четырёх таблиц и индексов, выполняются
целиком через `executescript()`. `sql/queries.sql` — одиннадцать
проверенных запросов с комментариями. `db/database.py` — путь к базе,
`get_connection()` с `row_factory = sqlite3.Row` и
`PRAGMA foreign_keys = ON`, создание схемы, функции `fetch_all()` и
`fetch_one()`. `db/import_json.py` — перенос данных из JSON в SQLite.
`db/repository.py` — SQL-выборки и сборка объектов `Guide`, `Route`,
`Excursion`, `Schedule` методами `from_data()`, поэтому шаблоны работают с
теми же объектами, что и раньше, а логика предметной области остаётся в
классах ПР3.

### 4.4. SQL-запросы проекта

В `sql/queries.sql` одиннадцать запросов:

1. список гидов — `SELECT` и `ORDER BY name`;
2. гиды, знающие английский, со стажем от пяти лет — `WHERE` +
   `LIKE '%английский%'` + `AND`;
3. активные занятия — `JOIN` трёх таблиц (`schedules`, `excursions`,
   `guides`) с отбором по статусу;
4. полная информация о занятии — `JOIN` четырёх таблиц (добавлен `routes`);
5. гиды, свободные на выбранную дату, — подзапрос `NOT IN`;
6. количество активных занятий — `COUNT(*)`;
7. занятия по гидам — `LEFT JOIN` + `GROUP BY` + `COUNT(s.id)`;
8. гиды, у которых больше одного занятия, — `HAVING COUNT(s.id) > 1`;
9. выручка и заполняемость по экскурсиям — `SUM(s.booked * e.base_price)`,
   `AVG` и `ROUND`;
10. пять ближайших занятий — `ORDER BY` + `LIMIT 5`;
11. сводка по базе — несколько `COUNT` в одном запросе.

### 4.5. Страницы на данных из базы

Из SQLite получают данные страницы `/guides/`, `/routes/`, `/excursions/`,
`/schedules/`, поиск свободных гидов `/guides/available/?date=2026-03-10`,
активные занятия `/schedules/active/` и статистика
`/schedules/statistics/`. Карточки `/guides/1/`, `/routes/1/`,
`/excursions/1/` и `/schedules/1/` также собираются по строкам базы.
Списки и карточки проходят через `db/repository.py`, а страница статистики
получает `sqlite3.Row` напрямую из SQL-запросов (в том числе с `GROUP BY`)
и читает поля по именам (`item.schedules_count`).

### 4.6. Параметризованные запросы

Значения передаются заполнителем `?` отдельным списком:
`fetch_one("SELECT * FROM guides WHERE id = ?;", [guide_id])`,
`fetch_all("... WHERE date = ? AND status <> 'отменена' ...", [schedule_date])`.
Подстановки пользовательских значений f-строками в текст SQL в проекте нет.
