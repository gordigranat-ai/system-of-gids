# Сервис управления туристическими гидами

Мой индивидуальный проект. Начинался как консольная программа для
экскурсионного бюро, а в ПР5 у него появился веб-интерфейс на Django:
гиды, маршруты, экскурсии и расписание доступны в браузере. В ПР6
веб-часть переведена на Django-шаблоны.

Готовы ПР1, ПР2, ПР3, ПР5 и ПР6.

## Что умеет

* гиды: список, поиск, отбор по языку и специализации, сортировка,
  добавление, удаление;
* маршруты: поиск, отбор по сложности и длительности, сортировка,
  добавление, удаление;
* экскурсии: поиск, отбор по цене и маршруту, расчёт стоимости со скидками;
* расписание: занятия на дату, по гиду и за период, добавление с проверкой
  занятости гида, бронирование и отмена мест, отмена занятия;
* статистика: загрузка гидов, популярность маршрутов, выручка, заполняемость
  занятий;
* данные сохраняются в JSON и загружаются при запуске;
* **в ПР5 добавился веб-интерфейс**: страницы гидов, маршрутов, экскурсий
  и расписания, а также собственная страница 404;
* **в ПР6 веб-часть переведена на шаблоны**: базовый шаблон с наследованием,
  включаемые части, циклы и условия, фильтры, именованные URL и собственные
  статические файлы.

## Предметная область

Есть гиды и маршруты. По маршруту создаётся экскурсия с ценой и ограничением
по числу участников. Конкретное проведение экскурсии — занятие в расписании:
дата, время, гид, забронированные места.

Что проверяет программа:

* гид проводит только те экскурсии, языки которых знает;
* один гид не может вести два занятия в одно время;
* мест нельзя забронировать больше, чем вмещает экскурсия;
* отменённое занятие не удаляется, но время гида не занимает.

## Классы

Классы предметной области остались в корневом `models.py` и используются
и консольной частью, и веб-интерфейсом:

| Класс | Что хранит | Что умеет |
| --- | --- | --- |
| `Guide` | id, имя, специализация, языки, стаж, рейтинг | проверять языки, отдавать статус |
| `Route` | id, название, длительность, сложность, протяжённость | проверять длительность |
| `Excursion` | id, название, объект маршрута, цена, места | проверять вместимость, считать стоимость |
| `FamilyExcursion` | то же | то же, но детям цена со скидкой 50 % |
| `Schedule` | id, объекты экскурсии и гида, дата, время, брони | бронировать места, отменяться |

`FamilyExcursion` — наследник `Excursion`. Метод `total_price()` один,
а результат разный: для ребёнка семейная экскурсия считает половину цены.
Это полиморфизм.

Занятие ссылается на экскурсию и гида, а маршрут берётся через экскурсию,
поэтому работает `schedule.excursion.route.name`.

## Веб-часть на Django

### Проект и приложения

Django-проект называется `guideservice` и лежит в репозитории рядом
с консольным приложением: `manage.py` находится в корне, поэтому ничего
переносить не пришлось.

| Приложение | За что отвечает |
| --- | --- |
| `homepage` | главная страница, общий каркас страниц, страница 404 |
| `guides` | гиды |
| `routes` | маршруты |
| `excursions` | экскурсии |
| `schedules` | расписание занятий |

Приложения зарегистрированы в `INSTALLED_APPS` в `guideservice/settings.py`.
Для пользователей отдельного приложения нет: Django уже предоставляет
встроенную модель `User` в `django.contrib.auth`.

### Страницы и адреса

| Страница | URL | View-функция |
| --- | --- | --- |
| Главная | `/` | `homepage.views.index` |
| Гиды | `/guides/` | `guides.views.guides` |
| Карточка гида | `/guides/<int:guide_id>/` | `guides.views.guide_detail` |
| Маршруты | `/routes/` | `routes.views.routes` |
| Карточка маршрута | `/routes/<int:route_id>/` | `routes.views.route_detail` |
| Экскурсии | `/excursions/` | `excursions.views.excursions` |
| Карточка экскурсии | `/excursions/<int:excursion_id>/` | `excursions.views.excursion_detail` |
| Расписание | `/schedules/` | `schedules.views.schedules` |
| Карточка занятия | `/schedules/<int:schedule_id>/` | `schedules.views.schedule_detail` |
| Страница 404 | любой несуществующий адрес | `homepage.views.page_not_found` |

Маршруты распределены по двум уровням: `guideservice/urls.py` подключает
маршруты приложений через `include()`, а конкретные адреса описаны
в `urls.py` каждого приложения. У всех приложений задан `app_name`, поэтому
маршруты имеют пространства имён: `homepage:index`, `guides:list`,
`guides:detail`, `routes:list`, `excursions:detail`, `schedules:list`
и так далее. В шаблонах ссылки строятся по этим именам, а не по жёстко
записанным адресам.

### Как запрос превращается в страницу

1. браузер отправляет GET-запрос на адрес;
2. `guideservice/urls.py` выбирает приложение по префиксу;
3. `urls.py` приложения находит view-функцию и передаёт ей параметры из адреса;
4. view-функция загружает данные средствами ПР3 (`storage.py`), находит
   нужный объект и собирает контекст;
5. `render()` подставляет контекст в шаблон, шаблон наследует `base.html`;
6. Django возвращает HTTP-ответ со страницей и кодом 200 или 404.

### Шаблоны

Веб-часть работает на Django Template Language. HTML в view-функциях
не собирается: view готовит контекст — словарь с данными — и вызывает
`render()`.

```
guideservice/templates/           шаблоны уровня проекта
├── base.html                     общий каркас всех страниц
├── not_found.html                общая страница «объект не найден»
└── includes/
    └── navigation.html           навигация, подключается через include

homepage/templates/homepage/      шаблоны приложений
guides/templates/guides/
routes/templates/routes/
excursions/templates/excursions/
schedules/templates/schedules/
```

Что используется:

| Возможность | Где применяется |
| --- | --- |
| наследование `{% extends %}` и блоки `{% block %}` | все страницы наследуют `base.html` и переопределяют `title` и `content` |
| include `{% include %}` | навигация, карточка гида, маршрута и экскурсии, статус занятия |
| контекст | `{"guides": ...}`, `{"guide": ..., "schedules": ...}` и другие |
| циклы `{% for %}` и `{% empty %}` | списки гидов, маршрутов, экскурсий, занятий |
| условия `{% if %}` | статус гида, статус занятия |
| именованные URL `{% url %}` | вся навигация и все внутренние ссылки |
| фильтры | `length`, `default`, `join`, `floatformat` |
| статические файлы `{% static %}` | собственный CSS, JavaScript и логотип |

Фильтры используются по назначению: `{{ guides|length }}` выводит количество
записей, `{{ guide.name|default:"Без имени" }}` подставляет текст, если
значение пустое, `{{ guide.languages|join:", " }}` склеивает список языков,
`{{ schedule.revenue|floatformat:0 }}` убирает дробную часть у суммы.
Фильтры только оформляют вывод и не заменяют расчёты: стоимость и скидки
по-прежнему считают методы классов.

### Оформление и статические файлы

Собственные статические файлы лежат в `homepage/static/homepage/`:

| Файл | Где используется |
| --- | --- |
| `css/style.css` | `base.html`, карточки гидов и маршрутов, статусы занятий |
| `js/main.js` | `base.html`: подставляет текущий год в подвал |
| `img/logo.png` | `base.html`: логотип в шапке сайта |

Подключение идёт через `{% load static %}` и `{% static '...' %}`.
Bootstrap 5.3 остаётся подключённым по CDN и отвечает за сетку и базовые
компоненты (`container`, `card`, `badge`, `btn`, `list-group`), а собственный
CSS проекта добавляет оформление: логотип, отступы, рамки карточек,
начертание статусов.

### Обработка ошибки 404

Собственная страница подключена через `handler404` в `guideservice/urls.py`.
Если объект с запрошенным id не найден, view-функция возвращает ответ
с кодом 404 и сообщением об ошибке.

Адрес настраивается: при `DEBUG = False` Django показывает собственную
страницу 404, при `DEBUG = True` — техническую страницу отладки. Переключать
режим можно без правки файла:

```
set DJANGO_DEBUG=0
python manage.py runserver
```

│   ├── settings.py
│   ├── urls.py

├── routes/              страницы маршрутов (templates/)
├── excursions/          страницы экскурсий (templates/)
├── schedules/           страницы расписания (templates/)
├── main.py              консольное меню и сценарии ПР1
├── models.py            классы предметной области и свои исключения
├── storage.py           загрузка и сохранение JSON
├── reports.py           статистика
├── utils.py             ввод, даты, печать таблиц

Модуль статистики называется `reports.py`, а не `statistics.py`: файл
с таким именем в корне проекта перекрыл бы стандартный модуль `statistics`,
и Django не смог бы загрузить драйвер базы данных.

## Данные

Четыре файла в `data/`. Связанные объекты хранятся идентификаторами:

```json
{
  "id": 1,
  "excursion_id": 1,
  "guide_id": 1,
  "date": "2026-03-10",
  "start_time": "10:00",
  "booked": 8,
  "status": "запланирована"
}
```

При загрузке по `excursion_id` и `guide_id` находятся объекты, и занятие
получает на них ссылки. Если файла нет — программа начнёт с пустых списков,
если JSON испорчен — скажет об этом и продолжит работу.

## Запуск

Консольная версия:

```
python main.py
```

Или двойным щелчком по `run.bat`.

Веб-версия: нужен Python 3.11+ и виртуальное окружение.

```
py -3.12 -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

После запуска открыть `http://127.0.0.1:8000/`.

`python manage.py migrate` нужен один раз: команда создаёт служебные таблицы
Django (сессии и администратор). Данные проекта при этом не затрагиваются —
они лежат в JSON.

## Тесты

```
python -m pytest
```

Тесты проверяют классы предметной области, работу с JSON и веб-интерфейс:
что каждая страница открывается, что несуществующие id дают код 404,
что навигация есть на всех страницах, что шаблоны и статические файлы
подключены.

## Проверка оформления

```
flake8 . --extend-exclude=.venv
```
